#### Задание 1: Изучить исходный код и выписать все бизнес-правила.

1. Если `balance < 0` или `rate_percent < 0` — Ошибка `ValueError`.
2. Если `months` не является целым числом или выходит за рамки от 1 до 120 — Ошибка `ValueError`.
3. Базовая формула расчёта: `Итог = balance * (1 + rate_percent / 100) ** months`.
4. Если `balance >= 1_000_000`, клиент получает бонус +0.5% к процентной ставке.
5. Если `is_vip == True`, клиент получает дополнительный бонус +0.25% к процентной ставке.
6. Итоговая сумма округляется до 2 знаков после запятой.

#### Задание 2: Определить: входные параметры, выходной параметр, допустимые и недопустимые значения, граничные значения.

##### Входные параметры:

1. `balance` (float) — сумма вклада.
2. `rate_percent` (float) — годовая процентная ставка.
3. `months` (int) — срок вклада в месяцах.
4. `is_vip` (bool) — наличие VIP-статуса.

##### Выходной параметр:

* `final_amount` (float) — итоговая сумма на счету после начисления процентов.

##### Допустимые и недопустимые значения:

Допустимые значения: 

1. `balance >= 0`
2. `rate_percent >= 0`
3. `months` от 1 до 120 (включительно)
4. `is_vip` равно `True` или `False`

Недопустимые значения:

1. `balance < 0`
2. `rate_percent < 0`
3. `months < 1` или `months > 120`, а также передача нецелого числа (float).

##### Граничные значения:

1. `balance`: `0` (минимум), `999_999.99` (граница перед бонусом), `1_000_000` (граница бонуса).
2. `months`: `1` (минимальный срок), `120` (максимальный срок).
3. `rate_percent`: `0` (минимальная ставка).

#### Задание 4: Написать автотесты на `pytest`

Исходный код находится в файле `main.py`. Автотесты находятся в файле `test.py`.

```python
import pytest
from main import calculate_interest

def test_zero_balance():
    # Нулевой баланс должен вернуть 0.0
    assert calculate_interest(0, 5, 1, False) == 0.0

def test_basic_calculation():
    # Обычный расчет без бонусов
    assert calculate_interest(1000, 10, 1, False) == 1100.0

def test_large_deposit_boundary_below():
    # Баланс чуть ниже 1 млн (бонус не применяется)
    assert calculate_interest(999999.99, 10, 1, False) == 1099999.99

def test_large_deposit_boundary_exact():
    # Ровно 1 млн (применяется бонус +0.5%)
    assert calculate_interest(1000000, 10, 1, False) == 1105000.0

def test_vip_client():
    # VIP клиент (бонус +0.25%)
    assert calculate_interest(1000, 10, 1, True) == 1102.5

def test_vip_and_large_deposit():
    # VIP + Крупный вклад (бонус +0.75%)
    assert calculate_interest(1000000, 10, 1, True) == 1107500.0

def test_min_months():
    # Минимальный срок (1 месяц)
    assert calculate_interest(1000, 10, 1, False) == 1100.0

def test_max_months():
    # Максимальный срок (120 месяцев)
    result = calculate_interest(1000, 10, 120, False)
    assert result > 1000
    assert isinstance(result, float)

def test_negative_balance():
    # Отрицательный баланс
    with pytest.raises(ValueError, match="Balance cannot be negative"):
        calculate_interest(-100, 10, 1, False)

def test_negative_rate():
    # Отрицательная процентная ставка
    with pytest.raises(ValueError, match="Rate cannot be negative"):
        calculate_interest(1000, -5, 1, False)

def test_invalid_months_zero():
    # Срок равен 0
    with pytest.raises(ValueError, match="Months must be an integer between 1 and 120"):
        calculate_interest(1000, 10, 0, False)

def test_invalid_months_too_high():
    # Срок больше 120
    with pytest.raises(ValueError, match="Months must be an integer between 1 and 120"):
        calculate_interest(1000, 10, 121, False)

def test_invalid_months_float():
    # Срок передан как float
    with pytest.raises(ValueError, match="Months must be an integer between 1 and 120"):
        calculate_interest(1000, 10, 1.5, False)
```

#### Какие риски остались?

Несмотря на высокое покрытие логики, остаются следующие риски:

1. **Обработка типов данных (TypeError):** Функция не защищена от передачи строк или других нечисловых типов. Вместо понятной бизнес-ошибки программа упадёт с системным `TypeError`.
2. **Точность вычислений (Float Precision):** Использование типа `float` для финансовых операций может привести к накоплению микро-погрешностей округления. В продакшене для таких задач рекомендуется использовать библиотеку `decimal.Decimal`.
3. **Отсутствие верхних границ:** Код не ограничивает максимальную сумму вклада или процентную ставку. Теоретически передача экстремальных значений может привести к математическому переполнению (`inf`) или нелогичным результатам.

#### Почему тестирование важно для качества ПО и жизненного цикла (SDLC)?

1. **Снижение стоимости дефектов:** Раннее обнаружение ошибок на этапе разработки (Unit-тестирование) обходится компании в десятки раз дешевле, чем исправление багов на этапе приёмки или после релиза в продакшен.
2. **Живая документация:** Автотесты являются самым актуальным описанием поведения системы. Новый разработчик может понять бизнес-логику и граничные случаи, просто изучив тесты, без необходимости читать устаревшую техническую документацию.
3. **Защита от регрессии:** При рефакторинге или добавлении нового функционала (например, новых типов вкладов) автоматические тесты мгновенно сигнализируют, если изменения нарушили ранее работавшую логику.
4. **Уточнение требований:** Процесс написания тест-кейсов заставляет аналитиков и разработчиков заранее продумывать «серые зоны» и пограничные состояния, что приводит к более качественному ТЗ ещё до начала активной фазы кодирования.
