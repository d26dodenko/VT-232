## Тестируемая система

**Restful-Booker**, открытое учебное API бронирования отелей: https://restful-booker.herokuapp.com (
документация: https://restful-booker.herokuapp.com/apidoc/index.html). Docker и локальный запуск не нужны, достаточно
Postman и доступа в интернет.

| Метод  | Эндпоинт        | Назначение                                             |
|--------|-----------------|--------------------------------------------------------|
| POST   | `/auth`         | получение токена (логин `admin`, пароль `password123`) |
| GET    | `/booking`      | список идентификаторов бронирований (с фильтрами)      |
| GET    | `/booking/{id}` | получение бронирования                                 |
| POST   | `/booking`      | создание бронирования                                  |
| PUT    | `/booking/{id}` | полное обновление (нужна авторизация)                  |
| PATCH  | `/booking/{id}` | частичное обновление (нужна авторизация)               |
| DELETE | `/booking/{id}` | удаление (нужна авторизация)                           |
| GET    | `/ping`         | проверка работоспособности                             |

## Баг-репорты

#### 1: API возвращает успешный ответ при неверном пароле

**Тест-кейс:** TC-10  
**Серьёзность:** Critical

**Шаги воспроизведения:**

1. Отправить POST `{{baseUrl}}/auth`
2. В теле запроса передать: `{"username": "admin", "password": "wrong"}`

**Ожидаемый результат:** Код 401 Unauthorized. Отказ в авторизации.  
**Фактический результат:** Код 200 OK. В теле ответа возвращается JSON с токеном.

#### 2: API принимает пустое тело запроса при авторизации

**Тест-кейс:** TC-11  
**Серьёзность:** High

**Шаги воспроизведения:**

1. Отправить POST `{{baseUrl}}/auth`
2. В теле запроса передать: `{}`

**Ожидаемый результат:** Код 400 Bad Request. Ошибка валидации обязательных полей.  
**Фактический результат:** Код 200 OK. Сервер возвращает успешный ответ.

#### 3: Некорректный код ответа при удалении ресурса

**Тест-кейс:** TC-08  
**Серьёзность:** Medium

**Шаги воспроизведения:**

1. Получить токен через POST `{{baseUrl}}/auth`
2. Создать бронирование через POST `{{baseUrl}}/booking`
3. Отправить DELETE `{{baseUrl}}/booking/{{bookingId}}` с заголовком `Cookie: token={{token}}`

**Ожидаемый результат:** Код 204 No Content или 200 OK. Ресурс удалён.  
**Фактический результат:** Код 201 Created. Сервер сообщает о создании ресурса при его удалении.

#### 4: Внутренняя ошибка сервера при синтаксически некорректном JSON

**Тест-кейс:** TC-15  
**Серьёзность:** High

**Шаги воспроизведения:**

1. Отправить POST `{{baseUrl}}/booking`
2. В теле запроса передать JSON с синтаксической ошибкой (например, лишняя запятая):

```json
{
  "firstname": "Vitaliy",
  "lastname": "Kurbanov",
  "totalprice": 100
}
```

**Ожидаемый результат:** Код 400 Bad Request. Ошибка парсинга JSON.  
**Фактический результат:** Код 500 Internal Server Error. Сервер падает с внутренней ошибкой.

#### 5: API принимает строку вместо числа в поле totalprice

**Тест-кейс:** TC-16  
**Серьёзность:** High

**Шаги воспроизведения:**

1. Отправить POST `{{baseUrl}}/booking`
2. В теле запроса передать: `"totalprice": "сто рублей"`

**Ожидаемый результат:** Код 400 Bad Request. Ошибка несоответствия типа данных.  
**Фактический результат:** Код 200 OK. Сервер принимает строку и создаёт бронирование.

#### 6: API создаёт бронирование при отсутствии обязательных полей

**Тест-кейс:** TC-17  
**Серьёзность:** Major

**Шаги воспроизведения:**

1. Отправить POST `{{baseUrl}}/booking`
2. В теле запроса передать только одно поле: `{"firstname": "Vitaliy"}`

**Ожидаемый результат:** Код 400 Bad Request. Ошибка отсутствия обязательных полей.  
**Фактический результат:** Код 200 OK (или 500). Сервер создаёт бронирование, подставляя дефолтные значения, либо падает
с ошибкой.

#### 7: API принимает нулевую стоимость бронирования

**Тест-кейс:** TC-18  
**Серьёзность:** Major

**Шаги воспроизведения:**

**Ожидаемый результат:** Код 400 Bad Request. Ошибка валидации бизнес-правил (цена не может быть 0).  
**Фактический результат:** Код 200 OK. Бронирование создаётся с нулевой ценой.
